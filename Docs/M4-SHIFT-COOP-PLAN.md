# M4 五分钟班岗与合作体验

日期：2026-10-04。用户已指示开发 M4；当前状态：开发与本机自动化验收已完成；真人与设备验收未完成。

依据：`P0-HIGH-FIDELITY-PLAN.md` §4 M4、`M0-BASELINE.md` 已定规则，以及 M3 的共享任务实现与验收记录。M3 的历史结果不自动作为 M4 通过证据。

## 实施范围

1. 正式 LAN 入口启动 300 秒、五架错峰航班的完整班岗。本地与房主共用任务规则；客户端镜像倒计时、任务、分数、完成数、星级和结束状态。归零停止移动与作业，完成结果保留，重试由权威端启动新局。
2. 同步实际对局回放及其播放状态，限制历史和网络包体积，重复快照与重复结算不得重复记账。视频导出、系统分享、云端进度仍归 M6。
3. 客户端退出后 bot 接管；房主主动退出或突然失联后，剩余客户端从最近收到的权威检查点接管。保留席位 ID、航班、车辆归属、货物、油枪/阀门/油渍、旅客及已完成结果。旧权威或旧局消息不能覆盖新状态。退出席位的 bot 行为不计入退出账号的参与记录。
4. 屏外搭档提示、双端结果与合作状态反馈；bot 使用相同交互和占用规则。本机 JSON 保存共同局数、送走架数、真人实际完成任务计数、上次同玩日期；按这些记录选择分工偏好，不记录语音或聊天。
5. 自动化覆盖完整班岗、归零、结果与回放、重试、双方退出以及房主异常失联；真人试玩记录上手与分工，双机验证网络和设备表现。

## 实施约束与解释

- 仍使用现有三机位关卡；M0 两机位建议早于当前关卡实现，本轮不回退已经验收的地图。
- M3 显式练习入口和六组回归保留，正式大厅入口切换为完整班岗。
- Core 不依赖 Unity；业务时间仅由 Pump/Step(dt) 推进。日期仅用于注入的持久化展示元数据。
- 突然掉线时能恢复的上限是最后收到的权威状态；失联期间客户端不自行推演再与原房主合并。恢复后不补扣失联检测耗时。需记录快照恢复边界，不能宣称零数据丢失或任意网络分区下绝不产生两个独立模拟。
- 真人体验、两台 Android、真实 OAuth 和独立安装包是否通过，以本轮实际证据为准；不可由编辑器或本机双进程代替。
- 不新增外部服务、付费依赖、语音、视频导出或公网联机。

## 并行实施分工

- 网络：模式/局身份/权威代次、快照协议、退出与接管、可靠重试、纯网络测试。
- 玩法：有限班岗、完整可恢复状态、结算冻结、回放记录与同步、运行时接管。
- 合作：大厅入口、HUD 与屏外提示、bot 记忆及持久化、合作偏好。
- 编排验收：代码接口整合、真实 UDP 剧本、Unity 检查与截图、结果记录。
