# PALM BAY 小岛机场 Demo 设计

## 文档范围

这是当前 Unity 切片的玩法说明与 playtest 记录基线。它描述的是一张本地可玩的低多边形小岛机场场景，不是完整 MVP，也不代表 PRD 中所有 P0 入口已经落地。

Demo 的核心问题是：两位地勤能否在五分钟的航班叠压里形成分工、共享车辆和临时救火，并在失误后愿意再试一局。当前版本把场景、模拟规则、桌面输入和 HUD 放在一起验证，方便先观察主循环是否成立。

验证状态需要单独说明：本机 Unity 兼容编辑器因授权客户端为 x86_64、无法在 arm64 上启动，本文不声称 Unity 编辑器运行验证通过。运行时代码与编辑器脚本已通过真实 Unity 程序集编译；核心状态机测试 10 组通过、192 条断言通过。图形运行与真人手感尚未验证。

## 场景与局内结构

场景是清爽的低多边形小岛机场。`AirportWorld.Build()` 生成奶油色可行走地面、四周青绿色海水、沙滩边缘、左侧设施、中间南北道路、斑马线、右侧两个停机位、码头、棕榈树、跑道标线、停机位灯和交通锥。左侧设施从北到南固定为：

| 设施 | 坐标 | 颜色 | 作用 |
| --- | --- | --- | --- |
| 餐食 | `(-7.5, 0, 4.8)` 交互点 | 橙色 | 下单、等待、取餐并送机 |
| 登机 | `(-7.5, 0, 1.6)` 交互点 | 青色 | 开放旅客队伍 |
| 行李 | `(-7.5, 0, -1.6)` 交互点 | 蓝色 | 交还到达行李、装载出发行李 |
| 燃油 | `(-7.5, 0, -4.8)` 交互点 | 黄色 | 由一名地勤补充燃油储备 |

道路中心为 `x=-3`，宽约 3；斑马线位于 `z=1.6`。飞机机位中心为 `(5, 0, 3.6)` 和 `(5, 0, -3.6)`，对应机位 A/B。接驳点为 `(1.4, 0, ±3.6)`，由场景和角色移动规则保留为空间。左侧建筑停在交互点以西，避免建筑体覆盖交互位置。

`AirportGame.Awake()` 会在机场场景上创建正交相机、方向光和 HUD。大厅复用同一张机场场景做简化预览：能看到机场、飞机和车辆，配合左侧大厅面板开始试玩；它不是 PRD 中的飞机内部机舱大厅，也没有衣柜、房间发现或邀请状态。

一局是一班五分钟的本地值班。`AirportSimulation` 的默认配置如下：

| 航班 | 到达时间 | 截止时间 | 默认目的地 |
| --- | ---: | ---: | --- |
| UBA826 | 0 秒 | 75 秒 | 北湾 |
| QMR152 | 35 秒 | 110 秒 | 珊瑚角 |
| AZU407 | 85 秒 | 160 秒 | 棕榈滩 |
| GLO219 | 140 秒 | 215 秒 | 蓝泻湖 |
| TAM638 | 195 秒 | 270 秒 | 港湾 |

班岗总长为 300 秒，只有两个机位。航班按到达先后占用空闲机位，未完成的航班会在自己的截止时间进入 `Missed`；两个机位都被占用时，新航班在队列中等待。这样形成 0/35/85/140/195 秒的错峰压力，玩家需要在当前飞机、下一架飞机和共享车辆之间重排优先级。

## 四类任务流程

四类任务的顺序和名称与 HUD、模拟枚举一致：餐食、行李、燃油、登机。每项服务完成一次会计入一个任务完成数；五架飞机最多 20 项任务。

### 餐食

1. 空手到餐食站点按交互键下单。
2. 餐食处理 5 秒，`MealProgress` 从 0 增长到 1；完成后产物留在出货口。
3. 取餐车到餐食站点，按键把餐食装到当前选中的航班。
4. 把餐车开到对应机位，按住交互约 2.5 秒完成餐食。

餐食已备好但没有取走时，继续下单只会提示“出货口被挡住了”。当前版本只模拟一份餐食和一个全局餐食状态，未实现通用多机器生产系统。

### 行李

1. 驾驶空行李车到当前机位，按键取下到达行李。
2. 把到达行李送回左侧行李站，按键交还；交还后该航班才允许装载出发行李。
3. 回到行李站，按键装载当前选中航班的出发行李。
4. 把行李车开到正确机位，按住交互约 2.5 秒完成行李。

行李车可以空车返回，也不需要额外处理脏物资。车辆是共享资源，车被一位地勤占用时另一位地勤需要等待或改做别的事。

### 燃油

1. 空手站在燃油站点按住交互，由一名地勤把全局 `FuelReserve` 补到 1；补满需要约 6 秒。
2. 另一位地勤拿燃油车到燃油站，按键把储备装到当前选中的航班。
3. 把燃油车开到正确机位，按住交互约 2.5 秒完成燃油。

`fuelOperator` 记录当前油泵操作者，避免两人同时增加同一储备。当前切片没有漫油和拖把任务；PRD 中的漫油是否保留仍需 playtest 决定。

### 登机

1. 选中正在服务的航班。
2. 当餐食和燃油完成后，空手到登机站点按交互键开放登机。
3. 系统生成 8 名旅客，按 0.65 秒间隔从登机站出发，先穿过 `z=1.6` 的道路，再前往对应机位。
4. 每名旅客抵达机位会推进该航班 `1/8` 的登机进度。

登机开放只检查餐食和燃油，行李可以并行处理，或在行李尚未完成时继续让旅客出发。这是当前代码的实际规则，不应向玩家描述成“必须先完成四项”。旅客会挡住驾驶中的车辆：地勤车辆靠近已出发旅客时会被移动规则拦回，因而产生可观察的错峰压力。

## 输入、角色与共享车辆

当前是同一台电脑的双人桌面控制，输入接口与移动端摇杆尚未接通：

| 玩家 | 移动 | 点按交互 | 按住交互 | 切换目标航班 |
| --- | --- | --- | --- | --- |
| P1 | `WASD` | `E` | `E` | `Q` |
| P2 | 方向键 | 右 `Shift` | 右 `Shift` | `Enter` |

`Esc` 暂停，`F1` 打开地勤手册。空手点按靠近的空闲车辆会接管它；带车时离开站点与机位的交互范围后点按可以放下车辆，车辆保留已装载货物。驾驶速度约为 3.6，空手速度约为 4.5。每位地勤一次只能拥有一辆车。

场景中固定生成三辆共享车：餐车、行李车和燃油车。它们分别承担对应服务，车辆数量构成吞吐上限。`Cart.Owner` 防止同一辆车被两人同时接管；行李、餐食和燃油交付也会检查车辆当前装载的航班是否与机位匹配。AirportWorld 删除了 primitive collider，因此车辆、角色和旅客的阻挡由 `AirportGame.Move()` 中的距离与区域规则显式处理，而不是物理碰撞。

单人模式把 P2 替换为一个规则式 bot。bot 会选择当前服务中的航班，寻找未被占用且仍有未完成任务的车辆，在站点与机位之间往返，并以约 0.35 秒的动作节奏交互。它能完成一局的基本链路，但当前没有账号级存留记忆，也没有联网掉线接管；“刚好不如真人”仍是调参目标，不是已验证结论。

## 压力、评分与结算

压力来自四件事的叠加：两个机位、五架错峰航班、每架 75 秒的服务窗口、三辆共享车。登机旅客还会在道路上形成可预判的临时阻挡。HUD 顶部显示两个机位的航班号、目的地、四项服务进度和离港倒计时，并通过五张状态卡展示整班航班进展与下次抵达时间；底部显示每位地勤当前目标与情境提示。

评分规则在 `AirportSimulation` 中实现：

- 每项服务第一次达到 100% 加 50 分。
- 飞机四项服务都完成后立即离港，加 150 分以及截止时间剩余秒数的整数奖励。
- 星级只看离港数量：送走 1 架为 1 星，2 架为 2 星，4 架为 3 星。HUD 结果页显示目标“1 / 2 / 4 架”。
- `MissedCount` 会记录错过的航班，但当前没有额外负分；超时的机会成本主要是失去离港和时间奖励。
- `TrafficStops` 当前记录放行旅客的批次数（尚未统计实际车辆停顿），不参与得分。

班岗结束后，结果页显示星级、送走数量、完成任务数和分数，提供“再试一次”“返回大厅”和暂未开放的“下一关”。下一关按钮只弹出“后续关卡还未解锁”的提示，不会进入下一关。

回放是每 0.25 秒采样一次状态，再以约 12 倍速重新设置角色、车辆、旅客和机位飞机的位置；记录内容包括两位地勤、三辆车的变换、车辆装载状态、机位当前飞机和旅客位置。它是状态采样重演，不是视频录制，也没有声音轨、视频文件、拖动进度或原生分享。

## 取消、送错与到时边界

- 同一辆车通过 `Cart.Owner` 互斥；燃油站通过 `fuelOperator` 互斥。没有覆盖所有场景对象的通用占用系统。
- 松开交互键会取消当前交付读条，部分交付进度 `Work` 清零，货物仍在车上；开离机位后点按放开车辆，其他地勤可以接手。
- 送到错误机位时只显示“送错机位！车上是……的货物”，不会推进错误航班，也不会清空车辆。把车开到正确机位仍可继续交付。
- 上述“可纠正”是试玩版刻意放宽的规则。PRD F10 的目标规则是送错后该航班该项任务不可完成且不追加额外惩罚；本切片暂未采用不可完成结果，必须在 playtest 中验证哪一种失误后果更能带来可归因的笑料而不是挫败。
- 到达截止时间时，未完成的服务停止接受操作并标记为错过；已完成的服务保留。模拟在同一时间点先检查完整航班再处理截止，因此恰好完成的完整航班优先离港。
- 300 秒班岗结束时，仍处于 `Scheduled` 或 `Servicing` 的航班会被标记为 `Missed`，局内移动和交互停止，已完成的任务和已经离港的航班保留在结算中。

因此，这个版本没有实现登录、LAN、在线联机、实时语音、原生分享或关系持久化。也没有跨局共同记录、金币、永久居住地、下一关内容、在线深链和局外 Meta。它用于验证本地玩法循环，不应被包装成完整 MVP 已交付。

## 15 分钟真人 playtest 观察清单

每组至少两位第一次接触本 Demo 的玩家；主持人只解释“这是五分钟机场班岗”和两组按键，不提前讲最优分工。记录具体时间、原话和发生前后的航班状态，不只记录最后送走了几架飞机。

### 流程安排

- [ ] **0–2 分钟：入场与第一次行动**。记录玩家是否知道从哪里开始、是否能在 30 秒内让两名角色移动、是否理解点按和按住的区别。不要代替玩家操作。
- [ ] **2–5 分钟：第一架飞机**。记录谁先看 HUD、谁先拿车、餐食等待期间是否主动找别的事做；观察玩家是否自然说出“放进去—等—取出来”的规则。
- [ ] **5–9 分钟：第二架飞机与共享资源**。让航班自然错峰，记录两人是否因为三辆车分配发生协商，是否会把车放在搭档容易接手的位置，是否能理解到达行李要先送回站点。
- [ ] **9–12 分钟：燃油接力与登机道路**。记录一人补油、另一人开车是否被理解为节省时间；观察玩家是否提前安排旅客放行，车辆被挡时说的是“我们应该晚点放行”还是“随机卡住了”。
- [ ] **12–15 分钟：失误、结算与再试意愿**。若自然发生送错机位，记录玩家是否能识别原因和修正路径；观察星级、回放、得分和“再试一次”按钮是否被理解，以及玩家是否主动讨论下一局分工。

### 每局必记

- [ ] 首次移动成功耗时；首次成功交互耗时；是否在 10 分钟内独立掌握全部按键。
- [ ] 第一次餐食下单、取餐和交付分别耗时多少；玩家是否知道餐食在等待而非卡死。
- [ ] 第一次到达行李是否主动返回行李站；是否把出发行李和到达行李混为一谈。
- [ ] 第一次车辆冲突的时间、双方怎么解决、是否出现“车不够用了”的自发分工语言。
- [ ] 燃油接力是否被视为合作节省时间；油泵被占用时是否知道换任务或等待。
- [ ] 登机开放前是否读到餐食/燃油门槛；旅客挡车后，玩家能否预判、干预并解释原因。
- [ ] HUD 被查看的次数和时机；不看飞机本体时能否根据顶部信息判断优先级。
- [ ] bot 是否被信任、接管是否可理解、bot 做错时玩家是接手还是放弃。
- [ ] 送错目标后的情绪：笑、甩锅、困惑、沉默或放弃；修正是否顺畅。
- [ ] 到时后的理解：玩家是否知道未完成任务失败但已完成任务保留；是否觉得倒计时过短、过长或刚好。
- [ ] 结算星级是否能复述“1/2/4 架”的目标；是否能看懂采样回放在回放什么；是否点击再试一次或返回大厅。

### 访谈问题

结束后只问能帮助判断设计的短问题：

1. “刚才最需要两个人同时配合的时刻是哪一个？为什么？”
2. “你们什么时候觉得车不够用？当时怎么决定谁拿哪辆？”
3. “旅客挡路是你们能提前安排的事情，还是感觉像随机阻碍？”
4. “送错机位时，你觉得应该保留修正机会，还是这架飞机该项任务应该锁死？为什么？”
5. “如果再玩一局，你们会先改变哪一个分工？”
6. “结算页最想点哪个按钮？回放是否像一段共同经历，还是只像位置移动？”

本次观察的重点是合作是否自然出现、失误是否可归因、压力是否可预判，以及玩家是否在看到结果后产生再试意愿。完成航班数量和星级是结果指标，不能替代对话、停顿、互相等待和重新分工的记录。
